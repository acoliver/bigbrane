CARD RESOURCES AGAINST THE CARD'S OWN CLAIMS (FIX-17). The card states its resources: the architecture (hidden width, precision, carried-state bits), the cost sizes, and for each task the width d, the rounds and the state words as formulas in the task's size. The math stage held every statement to them. Test them against what the card claims in its text, and report each contradiction as a finding of `kind` "resource_contradiction". Two forms to look for:

- A claim about the mechanism's resources that the stated formulas contradict: the card says its state is fixed, constant, bounded or independent of the input, while a task's d or state words grows with the task size (for example "fixed state" with a recall width of 4*K+8); or it states a cost or memory that a stated width cannot have.
- A capability claimed at a size the stated resources cannot hold: the bits the task needs at that size (copy L*log2(D), recall K*log2(V), nesting depth, the INDEX bound for keys before queries) exceed the carried bits at the stated width and precision (the carried-state budget when the card states one, else state words times precision bits). Check it with the conservation library at the claimed size.

A resource contradiction is settled by runnable code or a SymPy derivation, never by a citation. In `verify(witness)`, `witness.resources` is the frozen resources section shown above, `witness.evaluate(formula, {"K": 64})` evaluates one of its formulas, and `witness.conservation` has `storage_bound(state_bits, required_bits)`, `copy_check(state_bits, D, L, accuracy)`, `dyck_check(state_bits, depth, accuracy)`, `associative_recall_check(state_bits, K, V, accuracy)` and `streaming_index_bound(n, state_bits)`, each returning a dict whose `status` is "discharged" or "violated". Return `confirmed` True only when the code shows the contradiction from the stated values (for example two widths that differ at two sizes, or a check whose status is "violated"); quote the claim text with source "card", or the resource with source "resources", as the evidence. `used_by` names the obligations of the claims the contradiction concerns. A confirmed contradiction fails those claims with kill code `resource_contradiction`. A difference between a resource and a profile protocol value, or a resource the card never contradicts in its text, is not a contradiction.

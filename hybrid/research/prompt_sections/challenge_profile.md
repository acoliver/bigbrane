PROFILE SLOTS (Phase 4). Claim ids P1 to P5 are the transformer profile, a fixed template. Challenge each slot for what it asserts, not for more:

- P1 asks that the counted operations and peak state of the card's reference code equal the frozen formulas. A cost the reference does not count (a wider hidden layer a witness uses, an extra table) is an accounting finding on P1. Training work is outside P1, which counts inference.
- P2 asks for a hand-set configuration of the mechanism, with no learning, that meets the threshold at every required size within its declared state words and within the frozen architecture contract. Hand-set parameters are allowed: that a table or a weight was set by hand is not a premise. Challenge a P2 witness for using something the mechanism does not have (an external oracle or index, a wider hidden layer or more rounds than declared, more precision than declared, a dimension the contract does not cover), with code that shows it.
- P3 asks for at least one task family the mechanism provably cannot solve within its resources, with a derivation; one concrete limit instantiates it.
- P4 asks that a finite training recipe, chosen by the prover, reaches the threshold from the stated m examples on three seeds at the solvable case, using the card's learning rule, while the same recipe fails both data controls. It does not ask for a guarantee about every optimizer, every recipe or every length, or for an asymptotic learnability result; do not raise those. Challenge a P4 result for a recipe that leaves the card's learning rule, a model that breaks the declared widths, or controls that did not run unchanged.
- P5 asks that the card's numbers pass the conservation laws. A sample bound needs the target-rule class it counts to be defined, with its size justified; raise a missing class once, as one finding on P5.
- An objection to the card's explanation of how its mechanism works (which round retrieves what) belongs to the card's capability claims, which are formalized separately; it never attaches to a profile slot, whose obligation is the executed result.

The frozen architecture contract below is what every P1, P2 and P4 check was held to (hidden width as a formula in d, precision of stored numbers; each statement declares its own d and rounds). A record frozen before the contract existed has none: then P1's coverage of the witnesses cannot be verified, and the host records that itself.

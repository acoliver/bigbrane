PROFILE OBLIGATIONS (Phase 4). Some statements above are profile obligations (claim ids P1 to P5). Each source you write must implement the card's own mechanism as the card defines it, with its stated resources. A construction that solves a task with machinery the card does not have (an unbounded stack in a mechanism with a fixed state, a lookup over the whole input in a mechanism that only keeps a window) is a different mechanism; the challenger and the statement-match checker read your sources, and such a source fails the card. Where the card's mechanism cannot reach a required size, implement it faithfully and let the check fail there.

Source contracts (Python, no imports, NumPy as `np`, no names starting with an underscore, no eval, getattr or open):

- cost (P1): `init(sizes, ops) -> (params, state)`, `update(params, state, token, ops) -> state`, `predict(params, state, ops)`. Use only `ops.np` for array work; every array operation is counted, and every executed line is traced. The P1 COUNTING CONVENTION section gives the units: write each product the way the frozen accounting definition counts it (`@` is k units per output element, multiply then sum is 2k-1) and keep no extra numbers in the state that the state formula does not count. `init` does not receive n. A sigmoid the accounting charges one operation is `ops.np.sigmoid(x)`, which computes sigma(x) = 1/(1+exp(-x)); 1/(1+exp(x)) is sigma(-x), a different function. Do not probe for absent functions: the convention lists what `ops.np` has.
- construction (P2): `init(layout) -> state`, `update(state, token) -> state`, `predict(state) -> int`. `layout` holds the task's token ids and `size`; the TASK CONTRACT for each statement gives its exact fields at every size, the token order, whether tables are shuffled, the chain structure, when predict is called and the stream lengths, measured from the generator. Read the size from `layout['size']` and the vocabulary from `layout['vocab']`; recall's `n_keys` is the key universe, not the pair count. For copy the harness feeds, after the separator, the mechanism's own previous prediction, not the true symbol (self-fed continuation). The peak state size in words is measured at every size and must not exceed the statement's `state_words`.
- learnability (P4): `RECIPE = {...}` at module level (the training recipe you choose: initialization, optimizer, learning rate, epochs or passes, batch size), `learn(layout, examples, seed) -> params` following it, `init(layout, params) -> state`, `update(state, token) -> state`, `predict(state) -> int`. The same learn and RECIPE train the true data and both controls. `examples` is a list of {"tokens": [...], "queries": [[position, answer], ...]}; the answer is the token expected after reading tokens up to that position. Size the output layer from `layout['vocab']` (the number of token ids); never infer it from the largest integer in the layout or the data. Copy examples carry the true symbols after the separator, but the test feeds the trained model its own previous prediction there. `learn` must apply the card's own learning rule to the examples. The harness also trains on no examples and on examples with wrong answers; if both still reach the threshold, the rule did not come from the data and the check fails. All of it, on every seed, runs in one job under the CPU-time cap stated in the LEARNABILITY BUDGET section, after a timing probe that refuses a learner projected not to fit: write the training as batched, optimized NumPy linear algebra so it fits, and choose a recipe that both fits and learns.

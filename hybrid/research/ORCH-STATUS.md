## Running it

```
.venv-hybrid/bin/python -m hybrid.research run --config hybrid/config/run.toml [--run-dir runs/run-<UTC>] \
    [--n-explorers N] [--max-cards N] [--max-calls N] [--max-wall-s S] [--s5-mode podman|local] \
    [--routing llxprt|gateway]
.venv-hybrid/bin/python -m hybrid.research run --run-dir runs/<id> --resume [--routing ...]
.venv-hybrid/bin/python -m hybrid.research inspect runs/<id>
```

A new run refuses a non-empty run directory. `--resume` needs an existing `ledger.jsonl`. Command-line flags override the matching keys of `run.toml`. A copy of the config is stored as a `config` artifact at every start.

`--routing` picks the routing table in `hybrid/config/models.toml` (over `BIGBRANE_ROUTING`, which is over the file's `routing = "llxprt"`). When the chosen table uses the gateway, the run checks before it creates anything that the gateway answers `GET /v1/models` at the configured `base_url` with the bearer token (`BIGBRANE_GATEWAY_TOKEN`, or `~/.bigbrane-gateway/run-token` when the variable is unset) and serves every routed model id. Otherwise it exits with status 2 and prints the exact command to run, for example:

```
cannot start the run: gateway backend 'gateway' is not usable at http://127.0.0.1:8765/v1: no token (...)
Start it in another terminal (it writes ~/.bigbrane-gateway/run-token):
  .venv-hybrid/bin/python -m hybrid.gateway serve --port 8765
If `.venv-hybrid/bin/python -m hybrid.gateway status` shows a missing login, run:
  .venv-hybrid/bin/python -m hybrid.gateway login anthropic
  .venv-hybrid/bin/python -m hybrid.gateway login chatgpt
```

A rejected token prints the `export BIGBRANE_GATEWAY_TOKEN=$(cat ...)` line; a provider without a login prints only that provider's `login` command. `run_start` records the routing table, where it was chosen, and the gateway check result. The gateway itself is not started by the run; it stays a separate process with its own logins.

## What works

Every item below is covered by the unit tests (fake LLM, fake prior-art classifier, fake bench, and the real `LocalExecutor`, so toy examples, numeric checks and construct checks really execute). The live run section says which parts ran with real models.

- **Scheduler** (`orchestrator.py`). N explorer workers (asyncio tasks) plus one asyncio queue and `workers.Sx` workers per stage S1 to S6. A stage function returns the next stage or None. Per-role model concurrency is LLMClient's per-backend semaphore. The run ends when every explorer has stopped and no card is queued or in flight (`run_stop` with reason `complete`), or when a budget runs out (`run_stop` with the reason; workers are cancelled, the in-flight call is lost, and each card keeps its last recorded verdict). An unexpected exception in a worker stops the run and is re-raised (fail fast).
- **Invariant.** `_enqueue` refuses to queue a card for stage Sk (k >= 2) unless its verdict at S(k-1) is `pass`, and refuses S4 without an S3 `pass`. S5 also asserts the S4 pass.
- **Budgets** from `run.toml`: `max_cards` (S0 attempts, including duplicates and failed explorer calls), `max_calls` (LLMClient.complete calls, including prior-art calls made through the injected wrapper), `max_tokens`, `max_wall_s` (watchdog task). LLMClient's own `BudgetExceeded` also stops the run cleanly.
- **Resume.** Budget counters are rebuilt from `llm_call` events, card directories and `explore_failed` events. Queues are rebuilt from each card's latest status: S0 pass to S1, `pass` at Sk to S(k+1), `revise` at S1 back to S1 (the revision count is read from the ledger, so a used revision is not granted again). A card that is at S1 `revise` with all its revisions used, which is where a run started under the old gate leaves a card with fixable findings, is queued again, gets a fresh critic pass and is judged by the gate in force at resume: under the defaults it passes with residual findings instead of failing. The lens order is not changed by a resume: the seed is read back from the run's first `run_start` event (`lens_seed`), and a run that started before the seed was recorded resumes with seed 0, which is what it used. Terminal verdicts stay terminal. The wall budget is per invocation.
- **S0 explore** (`stages/s0_explore.py`). The explorer draft schema requires the optional theory_card fields `core_idea` (one sentence) and `source_transplant` (`object`, `source_ids`, `change`); `extensions` is optional. Transplant sources outside the given papers are dropped like references, and a transplant left with none fails the explore task. `card_created` records the transplant object and the core size (state objects, update and readout equations, extensions). Each task has a lens (one of 23 explorable seed lenses or 7 cross-lens pairings from `lenses.toml`, visited in a shuffled order whose seed is `run.seed` when set and otherwise a stable hash of the run id, recorded as `lens_seed` in `run_start`), 3 to 6 papers from `sample_for_lens` (split across both lenses for a pairing), summaries of the cards already in the run, the known-alternatives list (the 9 seed entries of `known_llm_alternatives_to_avoid_reinventing`, which is never assigned as a lens), and an operator. Operators: `new`; `mutate` (queued by S6 when a card has supported claims, or drawn with `p_mutate` among cards that passed S1); `cross` (two such cards, `p_cross`). Roles alternate `explorer` and `explorer_alt` by card index. The explorer returns a card draft validated against the theory_card schema minus the orchestrator fields; the orchestrator fills in id, version, parents, `created_by_call`, lens and status. References to papers the explorer was not given are dropped and recorded.
- **Diversity.** TF-IDF cosine (numpy, `stages/diversity.py`) of title, summary and mechanism text against every card in the run. At or above `diversity.threshold` the card is stored, gets an S0 `fail` verdict naming the nearest card and the cosine, and a `duplicate` event; it never enters S1. For an escape card the parent and its escape ancestors are left out of the comparison (see "Slot reserve and escape similarity" below).
- **S1** (`stages/s1_wellformed.py`). Salad critic (schema `salad_critic`) plus the toy example run in the executor (Podman, `--network=none`, labels `bigbrane.owner=bigbrane`, `bigbrane.run=<run id>`, `bigbrane.job=<job id>`). The last JSON line printed is compared with `expected` (rtol 1e-6, atol 1e-9, every expected key must be present). The critic sorts findings into `fatal` (dimension error, contradictory definition, unfalsifiable central claim) and `fixable` (missing definition, notation clash, underspecified step, vague secondary claim, arithmetic slip; at most 8). Gate: a fatal finding fails the card at once; no findings plus a reproduced toy passes; otherwise the card is revised while `s1.max_revisions` (default 2) remain. Once they are used up, `s1.pass_with_residual_fixable` (default true) decides: with no fatal finding and a reproduced toy example the card passes S1, its reasons list each remaining fixable finding as `residual: <kind> (<where>): <problem>`, and the findings are stored as an `s1_residual` artifact. A toy mismatch or crash after the last revision still fails the card, and so do fixable findings when the option is false (`gate: fixable findings remain after N revision(s)`). The revision prompt asks for fixes by tightening (define where used, merge, move to extensions) and `card_revised` records the core size. The critic judges the core only and no longer traces the toy example by hand. RESEARCH-SYSTEM-SPEC.md still says "one revision allowed" for S1; this file and `run.toml` are the current behavior.
- **S2** (`stages/s2_prior_art.py`). `classify_prior_art` with an injected `llm_complete` over LLMClient (role `prior_art`, `allow_web=False`); the literature module runs the searches. Each `literature_search` event is also written as one `literature_receipt` per source with the card id, which is what the dossier shows. Then the reduction critic (schema `reduction_critic`). The reduction critic also answers whether the core idea is a textbook construction from its source field applied without modification (`textbook_transplant`, `textbook_why`); this is recorded in the artifact and the verdict reasons and does not gate. A claimed reduction triggers a second reduction-critic call for `check_code`, which runs in the executor and must print `{"equivalent": bool, "max_abs_diff": ...}`. Gate, in order: `known_disproven` fails; a verified reduction gives `reduces_to_known` unless `difference_if_any` starts with `LEARNING_RULE:`; `novelty_unassessed` gives `undetermined` (see the section at the end); `prior_art_tested` fails unless a `prior_art_delta` call finds a specific untested element; `radical_enough: false` fails (`s2.require_radical`); otherwise pass. "Verified" means the check printed `equivalent: true`, or there is no runnable check and the critic's confidence is at least `s2.reduction_confidence`. A check that prints `equivalent: false` rejects the reduction.
- **S3** (`stages/s3_feasibility.py`). Formalizer obligations (complexity, one capacity or information obligation per capability, learnability), disprover attacks, up to `s3.max_checks` attack checks run in the executor (`{"disproved": bool}`), then `feasibility_judge_a` and `feasibility_judge_b` in parallel with identical input (card, obligations, attack results); neither sees the other's verdict. A card that passed S1 with residual findings has them appended to the formalizer and disprover user messages under "known open issues from S1" (built in `s3_feasibility.py` from the `s1_residual` artifact; the prompt files are unchanged, and the judges do not get this block). Gate: a confirmed disproof (attack succeeds and its check printed `disproved: true`) gives `infeasible_proved`; both feasible gives `pass`; both infeasible gives `infeasible_proved` when an attack survived or an obligation was refuted, else `fail`; anything else gets one more round, then `undetermined`. Since 2026-10-11 the stage also runs executed obligation checks before the judges and the gate has two more rules; see "Executed obligation checks in S3" below.
- **S4** (`stages/s4_construct.py`). The builder gets the card, `hybrid/bench/api.py` and the template. Static AST checks: imports limited to numpy, torch and a small standard-library list; no `open`, `exec`, `eval`, `__import__` and similar; no attention building blocks unless the card's total cost is at least quadratic. Then an executor job fits the candidate on random data, validates `predict_proba`, runs `hybrid.bench.api.check_causality` and `describe_problems`, and compares `describe()["params"]` with the floats found in the model's numpy and torch attributes (a factor of 4 either way is accepted). Two repair rounds with the problems fed back.
- **S5** (`stages/s5_evaluate.py`). `hybrid.bench.evaluate.evaluate_candidate` with the Podman `Executor` (or `LocalExecutor` with `--s5-mode local`, results marked untrusted) and `hybrid/config/bench_quick.toml` (all five tasks, train sizes 32 and 128, n-gram and GRU baselines, short scaling probe). The claimed exponent is parsed from the card's `total_sequence`. The raw bench JSON is stored as a `bench_raw` artifact and a summary in the research `bench_result` schema as `bench_result`, which the dossier renders. The spec says S5 has no pass or fail, but the store needs a verdict to advance a card, so S5 records `pass` when the candidate job produced results and `fail` when it did not.
- **S6** (`stages/s6_verdict.py`). The analyst gets the card's claims and falsifiers and the bench JSON verbatim, returns the claims ledger (schema `analyst`), stored as a `claims_ledger` artifact; the verdict reasons list every claim. Any supported claim queues a mutate task for the explorers (used only while card budget remains).
- **Inspect metrics.** `inspect` prints, and the report overview shows, a creativity block: textbook transplants versus modified ideas (latest S2 reduction critic per card, split by explorer model), the lenses of the cards that received a verdict at each stage, and the mean and maximum core size of the latest card versions.
- **Prompts.** One file per role or sub-task in `hybrid/research/prompts/`: explorer (shared by explorer and explorer_alt), salad_critic, prior_art (a verbatim copy of the literature module's two system prompts, checked by a test), prior_art_delta, reduction_critic, reduction_check, formalizer, disprover, feasibility_judge (shared by both judges), builder, analyst, falsifier_designer, obligation_checker. Each starts with `# prompt: <name>`. Three section files start with `# section: <name>` instead and are only appended to another prompt: `explorer_escape` (to the explorer system prompt for escape tasks) and `reduction_critic_escape`, `reduction_check_escape` (to the S2 user messages for escape cards).
- **Records.** Every model call is an `llm_call` event from LLMClient. Every executor job is an `executor` artifact (code, stdout, stderr, receipt) tied to the card, and its job id appears in the verdict's `by_calls`. Stage outputs are artifacts (`salad_critic`, `prior_art`, `reduction_critic`, `obligations`, `disproof`, `judges`, `obligation_check`, `s3_gate`, `candidate`, `construct_check`, `bench_raw`, `bench_result`, `claims_ledger`). Orchestrator events: `run_start`, `card_created`, `duplicate`, `card_revised`, `queued`, `stage_start`, `stage_verdict`, `stage_error`, `explore_failed`, `candidate_built`, `mutation_requested`, `escape_requested`, `escape_skipped`, `resume_requeued`, `run_stop`, `run_end`, `orchestrator_error`.

## Requests for other modules

- `hybrid/literature`: `classify_prior_art` returns evidence items with a `source` key that the research `prior_art` schema does not allow, so S2 strips it before storing. If the classifier labels a card non-novel but none of its evidence survives grounding, the research schema rejects the record (evidence required); S2 then keeps the label and records the missing evidence in the reasons. A grounded-evidence count in the result would make this explicit.
- `hybrid/bench`: the evaluator's `bigbrane.bench_result/1` output does not have the `per_task`, `baselines` and `scaling_slopes` keys that the research `bench_result` schema expects. S5 writes a mapped summary for the report and keeps the raw output as `bench_raw`. Either side could adopt the other's shape later.

- `hybrid/llm`: none needed. A schema retry inside one `complete()` counts once in the run's `max_calls` and twice in the LLMClient budget.

## Residual-pass change (run-20261010T181300Z in progress)

The salad critic kept finding smaller fixable issues every round (a falsifier threshold's arithmetic, an unstated operand precision), so under the old rule good cards would fail on nitpicks, and with two S1 workers for ten cards S1 was the bottleneck. Changes, all in config and stage code, none in `hybrid/research/prompts/`:

- S1 passes a card with residual fixable findings once revisions are used up (above). `s1.pass_with_residual_fixable = true` is in `run.toml` and is also the default when the key is missing. Fatal findings fail at once, as before.
- `run.toml` workers: S1 4, S2 3, S3 2, the rest unchanged.
- `run.seed` is no longer set in `run.toml`. Without it the lens order comes from a hash of the run id, so each new run visits the lenses in its own order; set `run.seed` to an integer to pin the order (`--resume` keeps the order the run began with).
- Tests: `test_orchestrator.py` (residual pass with reasons, artifact and S3 input; clean pass without the block; `max_revisions = 0`; fatal and toy mismatch after the last revision still fail; option off fails; resume of a run started under the old gate; lens seed derivation, recording and resume) and `test_orchestrator_units.py` (shipped config values, option default and validation, optional `run.seed`).

## Graveyard and escape operator (observed in run-20261010T181300Z)

The explorers kept proposing known architectures, and S2 caught every one. Of the 11 cards that had reached S2 in the resumed run at about 16:00 local time, 10 got `reduces_to_known` and 1 failed as not radical enough. The reductions by family: `other_known` 6, `linear_attention` 3, `hopfield_or_kernel_memory` 1. Every numeric check that printed a result found the card and the known form equal, with `max_abs_diff` between 0.0 and 3.5e-11. Examples:

- card-537e161c, in-context Koopman/EDMD: weighted RLS, the preconditioned delta rule and MesaNet's in-context least squares, with a multi-hop read (max_abs_diff 1.8e-11).
- card-6de11b01, a hippocampal episodic index: a gated delta rule with one-hot hashed keys over slots.
- card-582f8abf, a parity constraint reservoir: Z2-labeled union-find.
- card-14429dbc, an SDM/CLS gcd lattice: an exact-match hard-attention cache plus the classical most-specific lattice learner.
- card-1184f7a7, holographic displacement: diagonal, no-decay linear attention (the H3 form) with a phase normalization.
- card-7ec5e5c2, a naturality compiler: worklist closure of an automaton homomorphism.

The S2 gate did its job. The loop did not learn from it, because S0 never saw S2 verdicts: explorers returned to the linear-attention, fast-weight and delta-rule basin and to textbook data structures under new vocabulary.

Changes:

- **Graveyard in S0** (`hybrid/research/graveyard.py`, `stages/s0_explore.py`). Every explorer prompt gets a `GRAVEYARD` block after the existing card summaries: one line of at most 250 characters per earlier card with title, core idea and outcome. The outcome is `reduced at S2 to <reduces_to>: <one sentence of the critic's argument>` (the first sentence that says what the card is, skipping openers such as "This is not a renamed recurrence"), `died at Sk (<verdict>): <deciding reason>`, `finished S6: ...` or `alive at Sk`. Reductions come first, then deaths, finished and alive cards; this run before earlier runs; newest first; at most `explore.graveyard_max` lines (default 20). `explore.graveyard_runs` (default empty) lists other run directories whose cards are added under "Earlier runs". Those runs are read without the ledger lock and only through files the ledger has recorded, so a run another process is writing can be listed. Each entry must have a `ledger.jsonl` and is read once at start, so a bad entry stops the run before anything is created; a run cannot list itself.
- **Escape operator** (`orchestrator.py`, `stages/escape.py`, `stages/s0_explore.py`). A `reduces_to_known` verdict calls `ctx.on_reduction`, which queues an `escape` explore task with probability `explore.p_escape` (default 1.0; the draw is fixed per run and card). A request that would exceed the card slots left after queued mutations and escapes is skipped and recorded (`escape_skipped`, with the reason); accepted ones are recorded as `escape_requested`. Explorers take queued mutations first, then queued escapes, then draw as before. The escape task keeps the parent's lens. Its system prompt is `explorer.md` followed by the new `prompts/explorer_escape.md`; its user message adds the parent's reduction critic output (reduces_to, mapping, difference_if_any, why, confidence, reduction_outcome), the S2 verdict lines about the reduction, and the executed check (printed JSON and the check program, up to 6000 characters). On `--resume`, every card reduced at S2 without an escape child gets an escape request, which also covers cards reduced before this change.
- **non_reduction_argument.** Optional in `theory_card.schema.json` (`known_family`, `broken_invariant`, `why_unrepairable`), so old cards still validate. `draft_schema(escape=True)` requires it for escape drafts; for new, mutate and cross drafts the property is left out of the schema altogether. An S1 revision of a card that carries it must keep it.
- **Escape prompt** (`prompts/explorer_escape.md`). The parent is treated as a known model; renaming, gates, schedules, readout nonlinearities, feature maps, bigger states or a second memory beside it get reduced the same way. The explorer must name the property the mapping relies on (linear or additive state update, associativity, a write linear in the key, a fixed-size state, exact-match or similarity retrieval, a textbook algorithm on the token stream), break it in the core, and check its update against the family's form before answering, keeping in mind that a nonlinear recurrence is an RNN and a softmax over stored items is attention or Hopfield. `non_reduction_argument` names the family, the broken invariant with the step of the new mechanism that breaks it, and why no repair (change of basis, lifted state, feature map, gate or decay, second memory) recovers the family, naming the strongest repair.
- **Reduction critic for escape cards** (`stages/s2_prior_art.py`). ## Slot reserve and escape similarity

- **Slot reserve** (`explore.escape_reserve`, default 0.3 in `run.toml` and `run2.toml`). The reserve is `ceil(escape_reserve * max_cards)` card slots, recomputed at each start and at resume. A new, mutate or cross task takes a slot only if at least as many free slots remain as the escapes need: one for each queued escape, plus the reserve no escape has claimed. An escape request takes any free slot and is skipped only when every free slot is already queued for an escape. Claims count at request time; a resume also counts the escape tasks the ledger already started. An explorer that cannot take a normal slot waits until an escape is queued or a card leaves the pipeline, and stops when nothing is in flight. `run_start` records the reserve; `escape_skipped` records its state (slots, claimed, queued, held, free).
- **Escape chain in S0.** For an escape card the parent and each ancestor reached through consecutive escape steps are left out of the nearest-card comparison (`escape_chain` in `stages/escape.py`). The verdict reasons name the excluded ids. Mutate and cross cards are compared with every card, as before.
- **Consequences to watch.** A held slot stays unused when no escape is requested (no reductions, or `p_escape` 0), so the reserve costs budget in such runs; set `escape_reserve = 0` to turn it off. An escape can take the last free slot while a mutation waits in the queue; escapes take priority because they are the operator the reserve exists for.

## Executed obligation checks in S3 (2026-10-11)

FINAL-REPORT.md section 3.5 and section 5 item 5: on card-46dbb349 the judges split on a numerical stability obligation that judge A left open and judge B marked refuted on the strength of a disprover float32 check. Nothing in S3 could settle a disagreement like that. S3 now gives each obligation of a checkable kind an executed, machine-decided result before the judges vote, and the gate uses it.

- **Role `obligation_checker`** (`stages/obligation_checks.py`, new prompt file `prompts/obligation_checker.md`, schema `obligation_checks.checker_schema`). It runs after the disprover and sees the card and the formalizer's obligations, not the attacks. For each obligation (the name is an enum of the formalizer's names, one entry each) it gives a kind and a program or null: `complexity` (op counts, exponents in n, d, V), `capacity` (capacity or dimension counting), `algebraic` (identity or invariant), `numerical_stability` (bounded state under the stated ranges, precision and lengths), `learnability` and `other` (left to the judges, never run). The prompt fixes the program contract: sympy, numpy and the standard library, deterministic, last stdout line `{"status": "discharged" | "violated" | "unknown", "evidence": str, "counterexample": object | null}`, a counterexample required for `violated`, test the precision the card or the obligation states (float64 when neither states one). Routing: Haiku then Sonnet in every table (`llxprt`, `gateway`, `gateway_claude_local`); role settings effort low, 64000 output tokens (first set at medium and 24000; both Haiku and Sonnet hit the output cap on the live cards, see below).
- **Execution.** Each program runs in the executor through the existing job API (`CodeRunner.run`, Podman with no network and the `[executor]` caps; `LocalExecutor` in tests), purpose `obligation_check`. A first run that prints `discharged` or `violated` runs again (`obligation_check_replay`); the obligation counts as decided only when both runs print the same status and counterexample (the evidence text may differ). A crash, timeout, contract breach (bad status, empty evidence, a violation without a counterexample) or a disagreeing replay leaves it `unknown`. Other statuses: `not_checked` (judge-only kind, no program, or no entry from the checker; a program for a judge-only kind is ignored and noted) and `skipped` (over `s3.max_obligation_checks`). One `obligation_check` artifact per obligation: kind, optional flag, program, status, decided, replayed, evidence, counterexample, both runs (job id, status, printed JSON, stdout and stderr tails), problems. The checker call and every job id are in the S3 verdict's `by_calls`.
- **`optional`.** The formalizer schema (`contracts.FORMALIZER`) now requires `optional` per obligation. The formalizer prompt file is unchanged; the instruction is appended to its user message (`obligation_checks.OPTIONAL_NOTE`): optional is true only for an obligation no card claim rests on.
- **Judges.** Both judges get an `EXECUTED OBLIGATION CHECKS` block appended to their user message in code (`obligation_checks.judge_section`): each obligation's kind, status, whether a replay reproduced it, evidence, counterexample, problems, and the program (up to 4000 characters) with its job ids, plus how the gate uses the results. The judge prompt file is unchanged and the judges still never see each other's verdict.
- **Gate** (`s3_feasibility.py`), applied after each judging round, in this order. The deciding rule is the first verdict reason (`gate rule: <rule>`) and is stored in an `s3_gate` artifact with the votes, the effective votes, the contested obligations, the notes and whether every checkable obligation was discharged; each round's `judges` artifact carries the same gate block.
  1. `disproof`: a confirmed disproof (as before) gives `infeasible_proved`.
  2. `check_violation`: a decided `violated` on an obligation the formalizer did not mark optional gives `infeasible_proved`, whatever the judges voted.
  3. `check_settles_split`: when the votes differ and the judges disagree about an obligation that a check decided (a violation of an optional obligation does not count), every check-decided obligation takes the check's status in both judges' lists (`discharged`, or `refuted` for a violation) and each vote is derived again from the list (any refuted: infeasible; any open: undetermined; otherwise feasible). A judge whose vote does not follow from its own list keeps its vote. The derived votes go through the judge rules below.
  4. `judges`: both feasible gives `pass`, both infeasible gives `infeasible_proved` or `fail`, otherwise another round and then `undetermined` (as before). When every checkable obligation is discharged and neither judge says infeasible, a split between undetermined and feasible is left to the judges exactly as before; with two judges that means another round, then `undetermined`. The `s3_gate` artifact records `all_checkable_discharged` so these cases can be counted.

## Definitions, premises, circularity and conditional claims (2026-10-12)

What the first live card showed. Card-46dbb349's fixer listed six assumptions, all marked as doing work and all open. A1 to A4 were protocol and evaluation conventions (input sampling, how evaluation reads the model, what the simulation runner does, how an underspecified Gated DeltaNet baseline is built), A5 a cost-accounting convention, and A6 the per-token operation envelope, which restates the complexity claims. Every claim came out `unproven`, nothing in the stages could move an assumption out of `open`, and the challenger rightly gave no magic-X code for conventions.

**Definitions** (`D1`, `D2`, ...; kinds sampling, evaluation, accounting, baseline, notation, other) are conventions and protocol choices. The fixer lists them separately and each obligation names the ones it uses. They are frozen with the statements (each has a sha256 in the `math_statements` record and in the freeze event; `load_frozen` checks them), the prover receives them as `frozen_definitions`, and the statement-match role reads them with the statements in both calls. A definition has no status (the schema has no field for one) and is not on the ledger. The matcher says whether each is only a convention; a definition it finds substantive is a hidden premise and makes every statement that uses it a mismatch (`statement_mismatch`).

**Premises** (`A1`, ...; challenger-added `C1`, ...) are substantive claims about the mechanism, the data or the world that a proof relies on but does not prove. Each has `why_needed` and `testable_by`: `code` with a `measurement_plan` (measure, data, procedure, accept_if) or `citation` with a source (`arxiv` id or `openalex` work id or `doi:` lookup) and quote. A missing plan or citation is a host problem (one retry); a premise still missing it is frozen as written and then cannot let a claim advance. Statuses: `proven` and `measured` (an obligation that discharges it held; `measured` names the executed `math_check` artifact), `cited` (stage C verified the source), `circular`, `open`.

**Circularity.** In its compare call the statement-match role gets the card's claims and, for each premise, the claims it supports through the edges; it lists the claims each premise restates or implies. A premise that implies a claim it supports is `circular`, never `open`; the claim's status is `circular` and C fails with `circular:<id>`.

**Conditional claims and the gate** (`mathrecords`). Claim statuses in precedence order: `blocked`, `refuted`, `failed`, `circular`, `unproven` (an obligation not shown), `conditional` (all obligations hold at some tier, open premises listed in `open_premises`), `proven`, `proven_up_to_bound`, `observed`; plus `not_formalized`. A conditional phrase only prefixes the tier phrase, so an executed result is still never called proven. At M a conditional claim advances when each open premise is testable by code with a plan, or testable by citation with a source offered (verified at C). At C it advances only when each open premise is testable by code with a plan; a cited premise whose source did not verify stays open and blocks (`unproven:<id>`). The verdict lists `conditional` claims and `scheduled_measurements` (status `deferred_to_test_design`), which test design (Phase 10, `stages/t_design.py`) must schedule.

**Magic-X.** It still runs on every doing-work premise. For a premise testable by code, code that is missing, has no task, quotes text that is not the card's, or does not run is `magic_x_missing:<id>`, a challenge failure. For a premise testable by citation, missing code is recorded and is not a failure. Baseline + X reaching the claimed advantage still fails the card with `magic_x:<id>`.

**Cited premises** (`hybrid/research/citations.py`). Before the challenger call, stage C resolves each source: an arXiv id in the local index (`literature.local_index_path`, new `ArxivIndexReader.get`) or an OpenAlex work through `hybrid.literature` (cached and paced; a lookup that fails, for example without the OpenAlex key, leaves the premise open with the reason). The challenger sees the resolved record (title, abstract, year, URL) and answers `supports` with a `record_quote`; the premise is `cited` only when the source resolved, the answer supports it and the quote is text of the record's title or abstract. Every lookup and verification is a `challenge_check` event. The statement-match role no longer judges citations. Tests inject `StageContext.lookup_source`.

**Records and inspect.** The `assumption_ledger` artifact now holds `definitions` and `premises`; `math_verdict` adds `definitions`, `conditional`, `scheduled_measurements`, and at C `citations`, `definition_checks` and `circularity`; claim records carry `open_premises` and `circular_premises`; `math_decision` carries `premises` and `definitions`. `inspect` prints definitions, each premise with status, kind and testability (CIRCULAR flagged), conditional claims with their premises, and deferred measurements; the dossier has the same. Records written before this change (one `assumptions` list, `open_assumptions` on claims) still load: their entries show as premises whose testability was not recorded.

**Deferred.** A premise is `measured` today only through an executed obligation of the frozen statements; measuring a premise on real data from its plan is test design's job (Phase 10), and nothing schedules it yet. Premises the challenger adds carry no plan, so they block until a revision (stage V, Phase 8) restates them. Citation verification reads only titles and abstracts; a result stated only in a paper's body cannot verify. Resuming an M run frozen before this change is not supported (the record has no definitions); rerun the card.

**Ideas and lineages.** An idea is keyed by the mechanism signature of its card at creation (`hybrid.research.signature`), so a card that renames an earlier card's mechanism shares that card's counts. With `outcomes.enabled`, the outcome store seeds the signatures, lineages and counts of earlier runs, so restarting a recorded idea in a new run inherits its counts. Each card gets a `lineage_assigned` event.

| Model calls per lineage | `budgets.lineage.model_calls` | 200 | every stage call |

**Plugging a loop in.** A stage with a revision loop calls `ctx.book.after_round(card_id=, stage=, loop=, round_id=, failures=)` after each round that still fails, and revises only when it returns None. The call records the round (`loop_round`), checks for a stall, then the idea's count against the loop's cap, and for `send_back` whether the lineage has an idea slot left. A granted round is charged (`budget_charge`) before the revision is made; a refused one is recorded as `loop_stop` (not terminal: the stage's gate then decides the card) and returned. S1 now uses this call. Phase 7's refinement dialogue and send-back and stage V need only the call with their loop name; an unknown name is a `ValueError`. `failures` maps each failing id (a finding at a place, an obligation, a kill code) to its detail (a counterexample, the toy mismatch), and `round_id` names the round so that a resumed stage repeating it gets the recorded answer.

**Stall.** A round whose failing ids and detail hashes equal the previous round's for the same loop and key ends the loop with `stall:<loop>`. A new counterexample for the same obligation counts as progress. For the escape loop, an escape child that S2 reduces to its parent's family is a stall (`stall:escape`). In stage M, a prover round that repeats the previous round's failures is `stall:prover`.

**Repair scope.** `lineage.repair_scope(before, after, named)` lists the ids a repair changed, added or removed outside the failures it answers; `lineage.reject_repair` records a `repair_rejected` event and returns the round's failures plus a `repair_scope` entry, which the caller passes to `after_round`. A rejected repair uses a round without running checks, and the same rejected repair twice is a stall. Stage V is not built, so nothing calls these yet outside the tests.

**Kill codes.** A loop ended by its cap records `budget:<loop>`, a stall `stall:<loop>`; both forms (and the bare `budget`, `stall`) are in `outcomes.KILL_CODES`. A terminal stop (a model-call cap reached mid-stage, a lineage at its idea cap at S0) is the card's death and its only kill code. A non-terminal stop at the stage where the card died is added to the stage's own code, for example `["ill_formed:fixable", "stall:s1_revision"]`. A mutation stop never counts as a cause of death. Outcome records carry a `budget` block (lineage, idea key, rounds charged per loop, model calls, stops).

**Resume.** Every count is rebuilt from the ledger. A run started before Phase 8 has no budget events: its cards get lineages at resume (`lineage_assigned` with `legacy: true`, plus one `lineages_assigned_at_resume` event), and the S1 revisions they used are counted from their S1 `revise` verdicts, so no revision is granted twice. A copy of the first live run, `runs/run-20261010T000322Z`, resumes this way in the tests.

**Inspect.** The text summary has a loop budget block (caps, each lineage with its ideas and calls, each card's idea key, rounds per loop and calls, every stop with its kill code, rejected repairs), the overview page a "Loop budgets and stalls" section, and each dossier a "Loop budget" section. A run without budget events shows none of it.

**Tests** (`hybrid/tests/research/test_budgets.py`, 38 test functions, 61 cases): the stall and cap rule checked exhaustively against an independent oracle over every failure sequence of a five-symbol alphabet; S1 under a critic that always asks for revision, one that alternates, an explorer that renames the same idea, and a reviser that repeats the same failing repair; escape chains reduced to the same family and to alternating families; mutation and parent draws at a full lineage; idea and lineage model-call caps; prover stall and cap in M; resume of a Phase 8 run and of the pre-Phase-8 first live run; each named loop (`refinement`, `send_back`, `math_revision`) at its plan cap under always-new and alternating adversaries; math revision stall on the same obligations and counterexamples and progress on a new counterexample; renamed variants sharing a named loop's count; send-back lineage slots, also after a rebuild and through the outcome store; repair scope rejection then stall; a stand-in Phase 7 dialogue stage run under the orchestrator with three adversarial challengers, whose kill codes reach the ledger and the outcome store; and a randomized property test over 10 seeds in which every run ends by itself with every count inside its cap. `hybrid/tests/research`: 489 passed.

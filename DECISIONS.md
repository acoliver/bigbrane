# Bigbrane decisions

Andrew's instruction (2026-10-15): make the calls, record them here with the reason, and keep going until the system is reliable. He is asked only about things that need information he alone has. Each entry can be revisited; changing one means a new calibration.

Guiding rule: a verdict counts only if it rests on stated inputs and checked evidence (Lean or SymPy proof, SMT up to a bound, or executed code at the protocol sizes), and has survived an adversarial review by a different model family. Anything missing goes back to the card's author. Retries, extra attempts or looser thresholds are not used to make a verdict come out right.

| Id | Decision | Reason |
| --- | --- | --- |
| D1 | Compute target: total cost O(n^a) with a at most 1.5; state fixed or O(log n). Unchanged default. | Stated goal: well below quadratic, no ever-growing memory. |
| D2 | The S3 opinion judges are out of the gate. | Replaced by the math stage; opinions are not evidence. |
| D7 | Planted cards: agent-written from specs, sealed before the run (done in Phase 9 prep). The 4 valid-new (T7) cards get an adversarial review by a second model family before the run, and any card the reviewer breaks is replaced and resealed. | Keeps the planted set honest without a human in the loop. |
| D8 | Excluded families: transformer, SSM, linear attention, delta rule, as in families.toml. Hopfield-style memories and exact-match caches are judged case by case by the reduction check. | They are not one mechanism; the executed reduction check decides. |
| P3 | An acceptable limit must be about the mechanism (state, update or readout). A limit that follows only from the output vocabulary or the task encoding does not count. | A limit is supposed to show the mechanism's own boundary. |
| NS | "not shown" (prover ran out of attempts, or a premise stayed open) stays a separate verdict from "failed". It never counts as a pass. In calibration it is a miss against the answer key, and the cause is found and fixed. | Reports must separate "could not build" from "proved impossible"; neither may pass. |
| XC | A statement-match dispute the two judges cannot settle blocks the claim: the claim cannot pass until settled. A third judge from a different family settles it, and the dispute is recorded. | An unsettled translation is not checked evidence. |
| R | Sizes: cards state every resource (FIX-16); protocol values are host rules; the statement writer invents nothing. | K2 recall failures came from invented widths. |
| C17 | Capability and cost are judged at the same resources (FIX-17). For each P2 task the host substitutes the card's stated widths (task size s) into the verified cost and state formulas, and reports the skill scale b: the largest s = n^b with total cost at most n^1.5 and state at most n^0.5. The fixed-size target verdict (D1) is unchanged and is what calibration's answer key scores. In live runs a card needs b > 0 on at least one P2 task. | Recalling K pairs needs at least K log V bits of state for any mechanism (storage bound), so a fixed or O(log n) state forces b = 0 for every idea and would kill everything; the adversarial T7 review showed this. Sublinear state (at most n^0.5, against a transformer's n) is the honest version of "no ever-growing memory". Expected: transformer none (cost), LSTM with width Θ(K) b = 1/4, HMM and n-gram no growing skill. |
| B10 | Phase 10 bench: adopt the criterion revisions proposed in results/phase10-diag3-20261013T2009Z/summary.md (criteria 2, 4, 6, 9). Acceptance runs use the pinned one-thread Podman CPU container; MPS only for diagnostics. | Reproducibility over speed for acceptance evidence. |
| T7 | The 4 main and 3 held-back valid-new planted cards are replaced. All 4 main cards failed adversarial review: each stores data in an exact map, gives b = 0 under C17, and states no resources (55 missing items each). Replacements must pass the same review by a different model family (valid math, no reduction to an excluded family or a textbook structure, b > 0, complete resources, P1 to P5 in principle), and are resealed. If a slot cannot be filled with a card that survives review, the false-kill rate is computed on the valid cards that did survive, and the count is reported. | The false-kill metric is meaningless if its "valid" controls are not valid. |
| T7b | "Not known" for a planted valid-new card uses the pipeline's own rule (families.toml and the S2 executed reduction check): the card's general mechanism, its update, readout and learning rule with learned parameters, must not reduce to an excluded family or a textbook structure. The hand-set P2 witnesses may coincide with textbook structures, because at the protocol's small alphabets a direct-address array, queue or stack is optimal for every P2 skill; the transformer's own P2 recall witness is a lookup and K1 still passes. A constant-factor state match of a witness is not a reduction. | Two review sessions showed that judging witnesses makes every exact design "known" (eight designs, all for the same reason). That standard would also differ from what the live pipeline applies to real ideas, so planted valid cards would measure the wrong thing. |
| T7c | T7 fallback applied (2026-10-16). Three replacement sessions screened or built 13 designs; every one reduced to a textbook structure on its general learned mechanism, confirmed by executed checks (candidate C: 44,122 outputs compared, 0 mismatches against a deque encoding). The broken T7 cards are removed from both planted sets and the sets resealed; the false-kill rate uses the valid known-model cards (T5). A card that survives the live run can become a planted valid-new control later. In the planted metrics, a target-gate kill (fixed-size or coupled) of a valid card is reported separately and does not count as a false kill, as in calibration where K1 passes the profile and fails the target. | Hand-designing a valid new mechanism is the research problem itself; the reviewers rejecting reductions is the system working. |
| L | A card states its own P3 limits as card fields (task, size, resources, why), at the mechanism level (decision P3). The statement fixer formalizes the stated limits and invents none, as FIX-16 did for sizes. A card without a stated limit is `card_incomplete`. Lean lint problems (forbidden constructs, reserved words) are fed back to the fixer inside its revision rounds, so a renameable identifier never drops a statement after the last round. | Calibration 200147Z K1 run 3: no card states a limit, so the fixer invented one each run (positional table size in run 1; an unseen next bit in runs 2 and 3). In all 9 K1 runs across three calibrations the first fixer answer omitted P3. In run 3 the invented statement named a variable `prefix`, a Lean keyword, and was dropped after the last round, leaving P3 not shown. |
| B10t | The B10 thresholds stand as predeclared before any acceptance data: learned K8 control 0.25 (twice chance), tie margin 0.01, ceiling 0.95, unstable spread 0.5, repeat margin 0.1, rival state ratio 1.25, information-bound cap 0.05. They may not be changed after acceptance results are seen. The acceptance slice gets same-seed repeat attempts for every cell (criterion 9 repeatability needs them wherever onset is unstable, and which cells are unstable is not known in advance) and a long-copy length at which the criterion 6 bound is tested. | Thresholds chosen after seeing results would be tuning. Repeats for every cell avoid choosing which cells to repeat from the data. |
| SEQ | Order of slot use: the acceptance calibration runs alone on the 4 executor slots. When it is accepted, the Phase 10 acceptance sweep (207 jobs, about 25 h on 4 slots, from measured one-thread Podman CPU rates) and the Phase 9 planted run share the slots through hybrid/slots.py, planted first in the queue. Phase 11 starts only after both pass. | The calibration gates both later phases and should not be slowed; the bench and planted test are independent of each other. |
| M | Statement-to-claim matching also runs before the freeze, inside the statement fixer's revision rounds: a mismatch (matcher plus cross-check, the same roles and rules as at C) is fed back to the fixer as a problem. A P3 statement must be stated over the card's shared mechanism definitions (the update, state or readout the limit names). The match at C stays as the independent audit, and statements are still frozen before any proof. | Calibration 20261016T051933Z K1 run 2: P3 was Lean-proven at M, then blocked at C because the frozen statement was a generic list-indexing fact that never mentions the embed update the card's limit names (objection upheld by the Sonnet cross-check). | PR | The conformance audit (and every check that compares a card's reference code with its frozen equations) runs both sides under one host-supplied precision policy taken from the card's declared evaluation precision, and its check points and tolerance are protocol values set by the host. The fixer chooses neither. | Calibration 20261016T051933Z K2 run 2: O2 conformance was violated by a 6.34e-06 store-state gap at position 205 of n = 256. | MO | Measurement objects are a component role of their own. Definitions that belong to a test or bound (a P5 hypothesis class, a task generator, an evaluation set) are never mechanism parts and never become hidden-component (magic-X) premises; the host settles such a component by the frozen statement that defines it, and only if that statement held. A challenger that labels one of them an external component gets the role corrected by the host check, and a component that is actually supplied to the model at inference or training stays a mechanism or external part. | Calibration 20261016T051933Z K1 run 3: the challenger listed the P5 restricted hypothesis classes as an external component with no covering statement, although its own note said they were declared classes for the information experiment, not given to the model, and O13.a froze them. The host made a hidden-component premise from it, which the circularity check then judged circular with P5, so P5 was not shown. Runs 1 and 2 listed only mechanism and training parts. |

A card-run stopped by an environment failure (backend transport, unloaded model, context too small) is an invalid run, never a verdict; calibration reruns that card-run in a fresh directory and scores the rerun. Verdicts are never retried. | Calibration 20261016T141847Z: at 15:38Z something outside this project started `LM Studio --run-as-service`, which SIGKILLed the running app (system log); the next request auto-loaded Qwen at the 8192 default and K3 run 1's statement match failed at C. | SR | Stopping rule for gate work. Once one calibration passes on the full rule (or after the current calibration plus one rerun of invalid card-runs, if only environment failures remain), the 30-idea live batch (plan section 14) runs next, with no further preconditions: the planted test and the bench acceptance sweep no longer gate it. The batch is judged by what survives and why things die (section 14 criteria). No new gate precondition may be added before the batch runs; a defect found during the batch is fixed and logged, and the batch result stands. Whether the "is it new?" check is too strict is measured alongside the batch by a separate probe of known non-equivalent mechanisms, never as a gate. Survivors still go to the bench before any claim of beating a baseline. | Outside review 2026-10-17: a week of calibrations (FIX-8 to FIX-21) improved the gatekeeper without attempting discovery; every later phase was gated on the one before, and the list kept growing. Section 14 itself says zero survivors with specific kill reasons is a valid outcome. |
